# v0.1.2 — `-Theme` could not be used at all

2026-09-02. Found within the hour of tagging v0.1.1, by the first consumer that
tried to use the thing v0.1.1 pointed it at.

## What was wrong

v0.1.1's `-ColorBy` help says, in terms: *"To colour by a layer, name a colour
per classification in -Theme's KindColor map, which is the channel the renderer
actually reads."* That advice could not be followed. **Every** `-Theme` value
threw, including a scalar one, and including one whose key was correct.

`New-TemplateSetOverlay` merges the caller's keys over the backend's
`Config/theme.psd1` and then writes **the whole merged file** back out.
`Write-PowerShellDataFile` handled scalars only. PSGraphRender's theme.psd1
declares `KindColor`, `LinkColor` and `EdgeResolutionStyle` as maps, so the
writer met a hashtable on its first pass over a file the caller had barely
touched:

    Cannot write setting 'EdgeResolutionStyle': this writer handles scalars
    only and was given [Hashtable].

A key nobody passed, in a file nobody edited, from a parameter that appeared
to take a hashtable.

## Why nothing had noticed

**A parameter nobody can use has no wrong behaviour to report.** `-Theme` was
declared, documented, carried into the options object and covered by a test
that checked it *reached* the options object. Nothing rendered with one. The
first render that tried was the harness's own diagram, immediately after
v0.1.1 told it this was the way to colour by layer — which is the argument for
consuming your own advice on the same afternoon you write it.

## What changed

`Write-PowerShellDataFile` writes maps and lists as well as scalars,
recursively, with `$null` handled and empty maps and lists written as `@{}`
and `@()`. Its refusal now names the key **path** — `KindColor.Enum` rather
than `KindColor` — because a writer that refuses a nested value and points at
the top of the tree makes the reader search it.

A key's value is REPLACED, not deep-merged. Half a caller's `KindColor` and
half the backend's is a colour scheme neither of them wrote.

## Falsification

Reverting the writer and re-running turns three of the four new cases red,
each on the right thing: the nested render throws on `EdgeResolutionStyle`,
the refusal names `KindColor` rather than `KindColor.Enum`, and the round-trip
throws on an empty map. The fourth — the backend refusing a theme key it never
declared — stays green under both writers, which is correct: it is not what
changed.

`plans/0041-operator-ux/theme-gate-falsification.txt` in
AI.Agent.Claude.PowerShellModuleBuilder is the transcript.

## What did not change

The contract is untouched, still `0.1.0`, still versioned independently. The
view model, the battery, `-ColorBy` and the overlay's refusal of an undeclared
key are all as v0.1.1 left them.
