# v0.1.0 — the contract, the options, the battery

2026-08-29. The first release. Built with the harness project's plugin skills,
which is itself part of what this release measured.

## Why this module exists at all

PSGraphRender renders a view model and knows nothing about what the nodes are.
PSModuleGraph produces one and knows exactly what they are. Between them sits a
mapping — derive depth, count dependents, decide what becomes a metric, carry an
unresolved reference through rather than dropping it — and until now that
mapping lived inside the producer.

One producer can hold its own mapping. Two producers holding two copies of it
is where they start disagreeing about what depth means, and neither of them is
wrong, and the reports stop being comparable. This module is that mapping,
extracted before there was a second producer rather than after.

The stronger reason is the battery. A producer author can read a schema and
believe they conform. `tests/ProducerContract.Battery.ps1` is the executable
version of that belief, run against real output in the producer's own build.
Its last assertion — that the graph maps to a view model the *renderer* accepts
— is the one that catches a defect in **this** module, which is exactly the
class of defect a producer author would otherwise report as "the report is
broken".

## What the contract refuses, and why

`additionalProperties: false` at every level, so that a stored `depth` is a
validation error rather than a field nobody reads.

Depth is a function of the `parentId` chain. A producer that stores it has two
sources of truth for one fact, and nothing notices them disagreeing until a
layered layout puts a node in the wrong row six months later. So the contract
refuses to carry it and `ConvertTo-GraphRenderViewModel` derives it — one place,
one answer.

The same reasoning made containment `parentId` and never an edge. A `contains`
edge alongside a parent chain is the same duplication wearing a different hat,
and `Test-ProducerGraph` refuses `kind: contains` by name.

And an edge marked `resolved: false` must state a `reason`. A producer that
silently drops what it could not resolve reports a graph that looks complete and
is not; one that marks it unresolved without saying why reports a finding nobody
can act on. The fixture has an unresolvable module source in it deliberately,
because a rule with no case that exercises it is a rule nobody has run.

## What was built with the plugin, and what the plugin got wrong

The scaffold, build and test skills drove the layout, `build.ps1`,
`<Name>.build.ps1` and the Pester configuration. Three things they said were
worth having and would not have been obvious:

- **`Severity = @('ParseError','Error','Warning')`.** `ParseError` is its own
  severity outside `Error`, so the idiom every example shows turns the lint gate
  off for the one defect class that makes a module unloadable.
- **`Run.Throw`, never `Run.Exit`.** The second terminates the host process
  running the build.
- **Read the coverage threshold back off the result** rather than keeping a
  second copy of the number, because two thresholds in two places drift
  silently while both halves keep working.

Two places the skills were wrong or silent for this target, both recorded for
the harness:

- **The scaffold's manifest pattern makes `src/` un-importable.** `RootModule`
  names the *generated* psm1, which exists only in `output/`. That is correct
  for the build and it means `Import-Module src/<Name>/<Name>.psd1` fails —
  which is exactly what this pass's acceptance test does, and what PSGraphRender
  itself cannot do today. A committed dev-loader `.psm1` in `src/` resolves it:
  it dot-sources rather than concatenates, so `$script:ModuleRoot` means the
  same thing under both loaders. The skill does not mention the problem or the
  fix.
- **`PSUseSingularNouns` versus a mandated command name.** `New-GraphRenderOptions`
  is the name the ecosystem's contract fixes, and the analyzer wants
  `New-GraphRenderOption`. The exclusion is stated with its reason in
  `PSScriptAnalyzerSettings.psd1`; the skill's guidance to exclude only with a
  reason is what made that a deliberate act rather than a silent one.

## The bug worth writing down

`Get-ProducerGraphDepth` had a parameter `$Node` and a loop variable `$node`.
**PowerShell variable names are case-insensitive, so those are one variable.**
The first `foreach` enumerated the captured collection correctly while
overwriting the parameter with its last element; the second `foreach` then
iterated a single object. The result was a depth table with one entry out of
fifteen, no error, no warning, and a view model that failed the render contract
on `metrics.depth` being null — three layers away from the cause.

It was found by running, not by reading: the schema validation refused the view
model. Nothing about the source looked wrong, which is the recurring shape of
every defect this project has recorded. The parameter is `$InputNode` now, and
the reason is in the function's own help.

## What could not be verified

- **No real producer has run the battery.** Every assertion is exercised against
  a hand-written sample and against violating graphs built by mutating a
  known-good one — and the sample was written by the same pass that wrote the
  contract, which is the weakest kind of evidence there is. PSTerraformGraph is
  the first genuine test.
- **The contract has one designer's idea of a producer in it.** `type`, `scope`,
  `parentId` and the edge kinds were chosen against a Terraform-shaped and a
  PowerShell-shaped graph, both imagined. Whether they fit a domain nobody had
  in mind is unmeasured.
- **Nothing checks the rendered page is right.** The integration tests assert a
  document exists, is large, and contains its configuration. Whether the graph
  is laid out correctly or the links point where they claim is not seen by any
  gate here. PSGraphRender's browser gate covers the renderer; nothing covers
  what this module's mapping does to a drawn page.
- **The `RequiredModules` floor is a floor.** It accepts every PSGraphRender
  above 0.13.0, including one that changes the view model contract. Deliberate —
  a pin would make every renderer patch breaking — but it means the battery is
  the only thing standing between a renderer release and a broken consumer, and
  the battery only runs when somebody runs it.
