# v0.1.3 — a classification with a hyphen in it silently lost the whole theme

2026-09-02. The third patch of one afternoon, and each one was found by trying
to use the previous one.

## What was wrong

v0.1.2 made `-Theme` usable. The first real theme it was handed was a
`KindColor` map keyed by a producer's node types, two of which are
`cross-cutting` and `powershell-module`. The writer emitted them bare:

    KindColor = @{
        cross-cutting = '#F2C14E'
    }

`cross-cutting` unquoted is `cross` minus `cutting`, so the file failed to
parse **as a whole** — not the one key, the file. PSGraphRender then warned
that it could not read the theme, fell back to its built-in values, and drew a
perfectly good page in which every node was the fallback grey.

**That is the worst failure shape available**: a render that succeeds, looks
deliberate, and carries none of the meaning it was configured with. The only
notice was a warning on a stream the caller was not capturing.

A second defect sat beside it. The writer walked `$map.Keys`, and on a
hashtable PowerShell resolves a member name against the dictionary's ENTRIES
before its properties — so a map containing a key called `Keys` answers
`$map.Keys` with that entry's value, and the writer serialises the wrong
object. `Keys`, `Values` and `Count` are all things a producer might call a
node type. The identical trap had bitten v0.1.1's own new test three hours
earlier, from the other direction: `$entry.Values` returning every field of a
schema entry instead of the enum it declares.

## What changed

Keys are quoted when they are not bare identifiers, and left bare when they
are — so a generated overlay still reads like the hand-written backend file a
reader will diff it against. Map iteration goes through `.PSBase.Keys`, which
asks the dictionary rather than the adapter.

## Falsification

With v0.1.2's writer restored, two of the five cases go red: the hyphenated
classification (the theme raises one warning where zero are required, which is
the fallback happening) and the round trip (`Keys` walked as a value). The
three cases that are about v0.1.2's own fix stay green under both, which is
what says the two releases fixed different things.

`plans/0041-operator-ux/theme-gate-falsification.txt` in
AI.Agent.Claude.PowerShellModuleBuilder carries both transcripts.

## The pattern, since it is now three for three

Every defect in v0.1.1, v0.1.2 and v0.1.3 is the same shape: **something
declared, documented, and never driven end to end.** A `ValidateSet` copied
from another repository's list. A `-Theme` parameter tested as far as the
options object. A writer whose round trip was never round-tripped. None of
them had a wrong behaviour to report, because none of them had a behaviour.

The three were found in about four hours, each by the attempt to use the one
before it, by a consumer rendering a real diagram. That is the argument for
consuming your own advice on the same day you publish it, and it is cheaper
than the argument for more unit tests.
